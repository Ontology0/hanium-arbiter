컬처핏(Culture-Fit)

에이전트 협업의 권한을 연결하고
사람의 개입 지점을 찾다

기획의 출발과 전환

초기에는 온톨로지·KG-RAG로 생성 콘텐츠의 문화·역사 오류와 출처를 검토하는 멀티에이전트 검수를 계획했습니다. 긴 대화·검토 떠넘김·결정권자 부재를 문제로 삼아, 온톨로지·근거 추적과 사람의 검토 부담 완화라는 목표를 유지하면서 ‘누가 판단·실행할 권한이 있는가’로 초점을 옮겼습니다.

권한 기반 HITL　/　온톨로지형 관계 모델　/　근거 연결 브리핑　/　A2A · MCP

01 / PROBLEM

긴 대화 속, 다음 결정의 주인은?

“주인에게 확인하고 전달할게요.”
그다음 결정은 누가 맡아야 할까요?

이 표현만으로 실패나 무한 대화를 단정할 수 없습니다.
위임 범위, 실제 전달, 응답 대기를 구분할 근거가 필요합니다.

  • 긴 대화합의·쟁점·미결정사항이 섞여 사람이 따라가기 어렵습니다.
  • 권한 공백·충돌결정 담당자나 소유자 간 우선권이 불명확합니다.
  • 승인과 실행확인 약속·실제 전달·실행 완료를 구분해야 합니다.

어떤 결정에, 누구의 판단이, 왜 필요한지 제시합니다.

02 / FEATURES

권한과 근거를 함께 보는 관제

01근거 연결 브리핑

합의·쟁점·개입 후보를 정리하고 인용한 메시지 원문으로 이동합니다.

02범위별 권한 확인

소유자·범위·행동을 등록하고 철회·만료·조건과 우선권을 대조합니다.

03판단과 대화의 기록

결정함·지식맵·명시적 페이지 이동과 JSON·Markdown 내보내기를 제공합니다.

04기존 에이전트 연결

A2A·MCP와 코드·MD Skill을 제공하며, Slack 수신 브리지를 구현했습니다.

03 / AUTHORITY FIRST

결정 대상 × 사람의 위임 기록

위임은 작업 범위·행동별로 적용합니다. 서로 다른 소유자의 우선권에는 관련 소유자의 승인 기록이 필요하며, 미확인 조건은 자동 충족으로 보지 않습니다.

04 / KNOWLEDGE MODEL

권한 충돌과 지식 충돌을 구분합니다.

사람 → 에이전트 → 범위 / 행동
주장 ↔ 근거 ↔ 결정

누가 결정할 수 있는가는 위임 기록으로 판단합니다.
어떤 주장이 사실인가는 출처와 검증 대상으로 남깁니다.

유형과 관계를 명시한 로컬 그래프입니다. RDF/OWL 추론기나 자동 사실검증은 구현하지 않았습니다. 결정권·연결 인증·사실의 진위는 별도 정보입니다.

05 / VALIDATION SCOPE

구현과 확인된 검증 범위

25권한 판정 단위 테스트
6A2A SDK 연동 테스트
9MCP 연동 테스트

권한 판정 규칙과 실제 SDK 연결의 해당 테스트 경로를 확인했습니다. 프로토콜 테스트의 모델 응답은 대역을 사용합니다.

8개 시나리오 × 3정책 = 24회 고정 대본 실행은 제어 흐름 회귀 검증입니다. 실제 탐지 정확도·비용 절감·사용성 개선을 입증하지 않습니다.

07 / APPLICATION & NEXT

활용분야와 다음 검증

개인 에이전트 조율

각 소유자의 확인이 필요한 일정·구매·예약에서 위임 경계와 대기 이유를 파악하도록 돕습니다.

팀의 리뷰·승인 협업

담당자 부재와 상충하는 승인권을 구분하고 사람이 답할 결정 대상을 좁힙니다.

재사용 가능한 협업 관제

A2A·MCP를 연결 계층으로 활용하고, 코드·Markdown 지침의 오픈소스 제공을 목표로 합니다.

구현 / 후속 검증설치형 Skill 구현·설정/발견을 확인했습니다(OpenClaw 2026.3.11). 공개 릴리스와 Slack 실제 연결은 미완료입니다. 향후 권한 공백·충돌의 정밀도/재현율, 질문 대상 적절성, 불필요한 재승인, 지연·비용을 익명 실제 사례로 평가합니다.
