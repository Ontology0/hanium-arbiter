# 요구사항 정의서

> **이 문서가 요구사항의 단일 소스다.**
> 상태·진행률·이력은 여기 쓰지 않는다. 그건 `checklist.json`이 갖는다.
> 이 문서를 고치면 `tools/sync_checklist.py`가 `checklist.json`을 대조해 맞춘다.
> 둘이 어긋나면 `tests/test_sync.py`가 실패한다.

- 대상 시스템: 개인 소유 AI 에이전트 간 협업 충돌 중재 시스템 (가제)
- 설계 근거: `docs/design/v0.3.md`
- **현재 구현 상태: 요구사항 정의 단계. 구현된 기능 없음.**

## 표 읽는 법

| 열 | 뜻 |
|---|---|
| ID | `UR-` 사용자 / `FR-` 기능 / `NFR-` 비기능. 부여 후 재사용 금지 |
| 우선순위 | `must` = MVP 필수 / `should` = 있으면 좋음 / `later` = 이번 범위 밖 |
| 추적 | v0.3 설계 문서의 원 항목 번호 |

ID는 `checklist.json`의 키다. 바꾸면 이력이 끊긴다. 요구사항이 사라지면 지우지 말고 우선순위를 `dropped`로 바꿔라.

---

## 1. 사용자요구사항 (UR)

사용자가 이 시스템으로 무엇을 할 수 있어야 하는가. 화면과 직접 대응한다.

| ID | 요구사항 | 우선순위 | 추적 |
|---|---|---|---|
| UR-01 | 사용자는 만들고 싶은 앱을 자연어로 입력할 수 있다 | must | R1, S3 |
| UR-02 | 사용자는 시스템이 도출한 요구사항을 확인·수정·승인할 수 있다. 승인본이 이후 모든 판정의 기준점이 된다 | must | R2, S4 |
| UR-03 | 사용자는 자기 에이전트를 등록할 수 있다 (소유자·전송 경로·git 권한·브랜치 규칙) | must | F3, S5 |
| UR-04 | 사용자는 태스크 배정 제안을 수락하거나 거절할 수 있다 | must | R3, S6 |
| UR-05 | 사용자는 충돌 상세에서 후보별 근거를 좌우 비교로 볼 수 있다. 근거마다 등급 배지가 노출된다 | must | R17, S7 |
| UR-06 | 사용자는 에스컬레이션된 건에 대해 선택지를 고르거나 직접 지시를 입력할 수 있다 | must | R15, S8 |
| UR-07 | 사용자는 충돌→근거→판정→결과 타임라인을 조회할 수 있다 | must | R17, S9 |
| UR-08 | 사용자는 생성 결과를 샌드박스에서 빌드·프리뷰할 수 있다 | should | R18, S10 |
| UR-09 | 사용자는 판정·에스컬레이션 결과를 사람 채널 알림 카드로 받는다 | must | R16, S8 |
| UR-10 | 사용자는 프로젝트를 생성·조회·전환할 수 있다 | must | F1, S2 |
| UR-11 | 연구자는 전략별 실험 지표를 대시보드에서 비교할 수 있다 | later | S11, F16 |

> UR-11의 사용자는 팀원이 아니라 **우리(연구자)** 다. 내부용 화면이므로 MVP 밖.

## 2. 기능요구사항 (FR)

시스템이 내부적으로 수행해야 하는 동작.

### 2-1. 요구사항·역할

| ID | 요구사항 | 우선순위 | 추적 |
|---|---|---|---|
| FR-01 | 시스템은 자연어 요청을 요구사항 목록과 태스크로 분해한다 | must | F2 |
| FR-02 | 시스템은 승인된 요구사항을 판정 기준점으로 고정 보관한다 | must | R2 |
| FR-03 | 시스템은 태스크별 배정 제안을 생성하고 수락·거절을 수집한다 | must | F4 |
| FR-04 | 시스템은 중복 수락과 미배정을 충돌(C0)로 처리한다 | must | R4 |

### 2-2. 보고 수집

| ID | 요구사항 | 우선순위 | 추적 |
|---|---|---|---|
| FR-05 | 시스템은 `POST /reports`로 에이전트의 작업 보고를 수신한다 (경로 A) | must | R5, F5 |
| FR-06 | 시스템은 브랜치 push를 감지해 산출물을 수집한다 (경로 B) | must | R6, F6 |
| FR-07 | 시스템은 경로 A/B 보고를 동일 스키마로 정규화한다 | must | D4, N5 |
| FR-08 | 시스템은 보고에 포함된 commit SHA의 실재 여부를 검증한다 | must | R7 |
| FR-09 | 시스템은 해당 SHA를 체크아웃해 산출물을 추출한다 (API 스펙·DB 스키마·호출부) | must | F7 |

### 2-3. 충돌 탐지·근거

| ID | 요구사항 | 우선순위 | 추적 |
|---|---|---|---|
| FR-10 | 시스템은 C0~C4 충돌을 자동 탐지한다 | must | R8, F8 |
| FR-11 | 시스템은 각 후보의 근거를 CLAIMED / REFERENCED / VERIFIED로 등급화한다 | must | R9, F9 |
| FR-12 | 시스템은 REFERENCED 근거를 직접 재현(테스트 실행·스캔·diff)해 VERIFIED로 승격한다 | must | R10, F9 |
| FR-13 | 시스템은 재현 실행의 입력·출력·종료코드를 증거로 저장한다 | must | N1 |

### 2-4. 중재·요청

| ID | 요구사항 | 우선순위 | 추적 |
|---|---|---|---|
| FR-14 | 시스템은 근거를 정렬해 채택안·이유·확신도를 판정한다 | must | R11, F10 |
| FR-15 | 시스템은 근거가 부족한 후보에게 검증 요청을 보내고 타임아웃을 관리한다 | must | R12, F11 |
| FR-16 | 시스템은 채택 후 상충하는 쪽 소유자 에이전트에게 수정 요청을 발행한다. 코드를 직접 수정하지 않는다 | must | R13, F11 |
| FR-17 | 시스템은 중재 전략을 교체 가능한 형태로 구현한다 (동일 충돌을 전략만 바꿔 재실행 가능) | must | F10, D5 |
| FR-18 | 시스템은 판정 불가·고위험 건을 선택지로 만들어 사람에게 넘긴다 | must | R14, F12 |
| FR-19 | 시스템은 사람의 응답을 수집해 판정에 반영한다 | must | R15, F12 |
| FR-20 | 시스템은 판정·에스컬레이션 결과를 사람 채널로 발송한다 | must | R16, F13 |

### 2-5. 이력·결과

| ID | 요구사항 | 우선순위 | 추적 |
|---|---|---|---|
| FR-21 | 시스템은 충돌→근거→판정→결과를 타임라인으로 조회 가능하게 한다 | must | R17, F14 |
| FR-22 | 시스템은 격리 샌드박스에서 결과물을 빌드하고 프리뷰 URL을 제공한다 | should | R18, F15 |
| FR-23 | 시스템은 합성 충돌을 주입하고 전략별로 반복 실행해 지표를 집계한다 | later | F16 |
| FR-24 | 시스템은 에이전트×충돌유형 적중률을 누적한다 | later | F17, E1 |
| FR-25 | 시스템은 계정 인증과 프로젝트 CRUD를 제공한다 | must | F1 |

## 3. 비기능요구사항 (NFR)

동작이 아니라 **지켜야 할 성질**. 대부분 테스트로 강제한다.

| ID | 요구사항 | 우선순위 | 추적 | 검증 방법 |
|---|---|---|---|---|
| NFR-01 | 근거 레코드는 원본 그대로 보존되며 사후 수정되지 않는다 | must | N1 | append-only 테스트 |
| NFR-02 | 프로젝트별 비용·시간 상한을 초과하면 파이프라인을 중단한다 | must | N2 | 상한 초과 시뮬레이션 |
| NFR-03 | 에이전트 무응답은 타임아웃으로 처리하고 파이프라인은 계속 진행한다 | must | N3 | 무응답 시나리오 테스트 |
| NFR-04 | 외부 코드 실행은 격리 샌드박스 안에서만 수행한다 | must | N4 | 호스트 실행 경로 부재 검사 |
| NFR-05 | 중재 엔진은 보고 전송 경로(A/B)에 의존하지 않는다 | must | N5 | 동일 입력을 A/B로 넣어 판정 동일성 비교 |
| NFR-06 | 상태가 `done`인 요구사항은 대응 테스트를 최소 1개 보유한다 | must | (팀 규칙) | `tests/test_sync.py` |
| NFR-07 | 판정에 쓰인 근거와 그 등급은 결과와 함께 항상 노출된다 | must | S7 원칙 | 응답 스키마 테스트 |
| NFR-08 | 시스템은 에이전트의 비공개 로컬 컨텍스트를 요구하지 않는다 | must | 설계원칙 1 | (O4 확정 후 구체화) |
