# 사용자 제공 참고문헌 43개 검증 기록

확인일: **2026-10-29 (Asia/Seoul)**. 대상은 사용자가 전달한 References [1]–[43]이다. 번호와 사용자 제공 서지는 보존하고, 직접 확인한 정보와 사용 제안을 별도로 기록했다. 아래의 **채택 분류는 자료정리 담당자의 제안**이며, 문헌의 주장이나 현재 구현 상태가 아니다.

## 검증 범위와 결과

- **arXiv ID가 있는 24개 모두** 해당 ID의 공식 페이지에서 제목·저자·최초 제출연도와 초록을 대조했다. **제목과 arXiv ID가 다른 논문을 가리키는 사례는 발견하지 못했다.** 이는 논문의 모든 주장·실험·참고문헌까지 검증했다는 뜻이 아니다.
- 아래 표 기준 **핵심 서지 일치 35개**, **저자 표기 보완 1개([27])**, **부분 확인 5개([5], [12], [20], [30], [43])**, **원문 미확인 2개([8], [22])**이다. 핵심 서지는 제목·저자·연도·제공된 식별자를 뜻하며, 권·호·쪽수 등을 재확인하지 못한 경우 해당 행에 명시했다.
- [16]의 **1997은 IJCAI 원출판 연도**, 1998은 arXiv 등록연도이다. 연도 오류로 처리하지 않는다. [40]의 사용자 표기 **Wölflein, G.**는 Georg Wölflein과 일치한다.
- [12]의 현재 URL은 **2026-10-11 개정판**으로 제목과 본문이 바뀌었다. [8]은 Respan 블로그 목록, [22]는 SmythOS GitHub 저장소로 이동한다. 현재 페이지를 2025년 원문 그대로 읽었다고 표시하지 않는다.
- DOI가 제공된 [29]는 Springer의 제목·저자·2023년·DOI가 일치한다. 접근 오류 자체를 문헌의 부재나 허위로 판정하지 않았다.

확인 범위 표기: **M** = 발행처·arXiv·저자 기관의 서지 메타데이터, **A** = 초록, **T** = 본문의 명시된 부분 또는 웹 글, **I** = 학술 색인 기록만 확인. **T도 실험 재현이나 논문 전체의 참·거짓 검증을 뜻하지 않는다.** 검색결과 요약만으로 기술적 주장을 채택하지 않았다. 현재 사양은 공식 문서로 교차 확인하고, 2025년 논문을 현행 프로토콜 사양처럼 사용하지 않는다.

## 보고서에서 우선 사용할 근거와 한계

사용자가 별도로 제공한 주 논문 **Qiaomu Li·Ying Xie (2025), [From Glue-Code to Protocols: A Critical Analysis of A2A and MCP Integration for Scalable Agent Systems](https://arxiv.org/abs/2505.03864)**는 위 43개에 포함되지 않는다. 해당 논문의 참고문헌에 실려 있다는 사실만으로 [1]–[43]의 정확성이나 관련성이 검증되는 것은 아니다. 본 감사에서는 주 논문의 제목·저자·연도·초록을 확인했고, 통합정리는 [source-synthesis.md](source-synthesis.md)를 참조한다.

1. **프로토콜의 역할**: [1]·[2]와 [A2A 공식 비교 문서](https://a2a-protocol.org/latest/topics/a2a-and-mcp/), [MCP 공식 아키텍처](https://modelcontextprotocol.io/docs/learn/architecture)를 우선한다. A2A는 에이전트 간 작업·상태 교환, MCP는 도구·맥락 제공을 설명한다. 연결 성공만으로 누가 특정 업무 결정을 할 권한이 있는지 판정되지는 않는다. 열람 당시 MCP `learn/architecture`는 `docs/2026-07-28/learn/architecture`로 이동했다. 실제 구현과 대조할 때는 사용 SDK·프로토콜 버전을 별도로 고정해야 한다.
2. **권한과 인간 감독**: [3]·[28]의 검증된 신원, 범위·조건에 따른 접근 정책과 [13]의 인간 감독 논의를 연결할 수 있다. 다만 소유자 간 업무 결정권 충돌을 탐지하고 적절한 사람에게 구체적인 질문을 만드는 방법은 **Arbiter가 제안하고 검증해야 할 별도 설계**이다. 신뢰·평판 점수, 모델 성능, Agent Card의 자기소개만으로 위임 권한을 인정하지 않는다는 원칙도 프로젝트 설계로 명시한다.
3. **의미·온톨로지**: [16]은 발화 행위와 대화 규칙의 역사적 근거이고, [6]은 프로토콜 분류의 근거다. 이 자료들만으로 `사람 → 위임 → 에이전트 → 대상·행동·조건`이라는 프로젝트 온톨로지가 표준이거나 최초라고 말할 수 없다. 사실이 맞는지와 누가 결정할 권한이 있는지는 다른 판정 문제다.
4. **평가 설계 후보**: [27]·[37]–[39]는 협업 비용·도구 오류·상태 있는 대화 평가를 검토할 때 유용하다. 현재 감사는 이 논문들의 실험을 재현하지 않았다. Arbiter의 실제 HITL 탐지 정확도, 불필요한 재승인 감소, 실행 전환율, 사용자 이해도, 토큰·시간 비용은 별도 실험이 필요하다.

## 남은 확인 작업

- [5]의 원래 발행일과 [12]의 2025년 판본을 확보하면 날짜·판본 기록을 보완한다. [8]·[22]는 원문 또는 보존본을 찾기 전 핵심 참고문헌에서 제외한다.
- [20]·[30]·[43]은 색인 기록까지만 확인했다. 본문 주장이나 수치를 인용하려면 발행처·저자 사본을 확보한다. [14]의 권호와 [18]의 호·쪽수는 최종 참고문헌 형식 정리 시 추가 대조한다.
- arXiv 개정판을 읽고 최초 제출연도로 인용하는 경우 판본을 함께 적는다. [42]처럼 사용자가 버전을 지정한 항목은 해당 버전을 유지한다. 학회 채택·저널 게재 여부는 저장소의 저자 표기와 출판사 확인을 구분한다.
- 이 문서는 자료의 식별·접근·관련성을 감사한 기록이다. **권한 기반 HITL의 독창성, 실제 Slack 연동, 다중 소유자 인증, Skill/MCP 공개 배포, 탐지 성능 또는 사용자 효과를 검증한 결과가 아니다.**
