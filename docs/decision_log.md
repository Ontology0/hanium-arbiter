## 확정

### D1. 과제 주제를 컬처핏에서 본 주제로 교체 (2026-08-11)

- **이전 주제:** 컬처핏(Culture-Fit) — 온톨로지 기반 생성형 AI 콘텐츠 문화·역사 고증 (KG-RAG)
  - 최초 정리 2026-05-09, 개발보고서 양식 수령 2026-07-12
- **변경 후:** 멀티에이전트 바이브코딩 중재 시스템
- **⚠️ 미확인 사항:** 한이음 드림업 운영 규정상 과제 주제 변경에 멘토·운영측 승인이 필요한지 **확인되지 않음.** 확인 전까지 이 결정은 팀 내부 결정일 뿐이다. → 아래 O0 참조

### D2. 에이전트를 직접 만들지 않는다

각 팀원 개인 계정·개인 PC에서 도는 봇을 그대로 사용. 내부 프롬프트·컨텍스트는 관측 불가로 간주.

### D3. 중재기에 코드 수정 권한을 주지 않는다

판정 후 소유자 에이전트에게 수정 *요청*만 발행. 직접 커밋 금지.

### D4. 보고 수집 경로 2개를 모두 수용

- 경로 A: 에이전트가 `POST /reports`로 직접 보고
- 경로 B: 브랜치 push 감지

`report` 테이블을 A/B 공통 정규화 지점으로 두어, 중재 엔진은 전송 경로를 모르게 한다 (요구사항 N5).

### D5. 실험 트랙과 자연 트랙을 처음부터 분리

- 자연 트랙: 실제 팀 3명 + 실제 레포 → "충돌이 자연 발생한다"는 증명용
- 실험 트랙: 컨테이너 3개 + 로컬 bare 레포 → 전략 비교 수치용

중재 수집 코드는 양쪽 동일. 나중에 붙이면 전부 뜯어고쳐야 하므로 선분리.

### D6. 스택

React + FastAPI + SQLite.

## 열린 이슈

### O0. 한이음 과제 변경 승인 절차 ⚠️ 최우선

주제를 바꾸려면 어떤 절차가 필요한지 확인 필요. 확인처: 한이음 포털 공지사항, 배정 멘토, 운영 담당자.
**이게 안 풀리면 아래 이슈들은 전부 무의미하므로 최우선.**

### O1. 실험 트랙 컨테이너의 모델 조합

Claude 단일로 갈지, 이종 모델 혼합으로 갈지. 이종 혼합이 충돌을 더 잘 만들 가능성이 있으나 비용·재현성 부담.

### O2. 합성 충돌의 정답 라벨링 방식

- C1(인터페이스), C2(데이터 모델) — 자동 생성·자동 라벨링 가능해 보임
- C3(품질 게이트) — 가치 판단이 섞여 사람 라벨링 필요할 가능성

두 경로를 분리해야 하는지 확정 필요.

### O3. 코드 실행 샌드박스

Docker 로컬 vs 외부 서비스. 근거 재현(테스트 실행·스캔)이 이 위에서 돌기 때문에 F9의 전제 조건.

### O4. 개인 에이전트의 비공개 컨텍스트를 어디까지 요구할 것인가

프라이버시 항목으로 발표에 넣을 만한 주제.

### O5. 실험 반복 비용

전략 4종 × 케이스 N개. 개발비보다 클 수 있음. 상한(N2: 프로젝트별 비용·시간 상한 초과 시 중단)을 먼저 정해야 함.

### O6. 프로젝트 정식 명칭

현재 가제 상태. 레포명 `hanium-arbiter`도 임시.
