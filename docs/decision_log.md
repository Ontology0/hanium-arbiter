  - 확인 경로·근거 문서는 추후 보강 필요 (멘토 회신, 포털 공지 등 기록으로 남길 것)

### D2. 에이전트를 직접 만들지 않는다

각 팀원 개인 계정·개인 PC에서 도는 봇을 그대로 사용. 내부 프롬프트·컨텍스트는 관측 불가로 간주.

### D3. 중재기에 코드 수정 권한을 주지 않는다

판정 후 소유자 에이전트에게 수정 *요청*만 발행. 직접 커밋 금지.

### D4. 보고 수집 경로 2개를 모두 수용

- 경로 A: 에이전트가 `POST /reports`로 직접 보고
- 경로 B: 브랜치 push 감지

`report` 테이블을 A/B 공통 정규화 지점으로 두어, 중재 엔진은 전송 경로를 모르게 한다 (요구사항 N5).

### D5. 실험 트랙과 자연 트랙을 처음부터 분리

- 자연 트랙: 실제 팀 3명 + 실제 레포 → "충돌이 자연 발생한다"는 증명용
- 실험 트랙: 컨테이너 3개 + 로컬 bare 레포 → 전략 비교 수치용

중재 수집 코드는 양쪽 동일. 나중에 붙이면 전부 뜯어고쳐야 하므로 선분리.

### D6. 스택

React + FastAPI + SQLite.

### D7. 코드 실행 샌드박스는 외부 서비스 (2026-08-13)

- **결정:** 근거 재현(테스트 실행·스캔·diff)은 외부 샌드박스 서비스에서 돌린다
- **이유:** 팀원마다 PC 사양·OS가 달라 Docker 로컬은 재현성이 깨짐. 외부 서비스는 누가 돌려도 같은 환경
- **기각:** Docker 로컬, 하이브리드(개발은 로컬·프리뷰만 외부)
- 요구사항 단위 기록: `checklist.json` D-0001 (FR-12, FR-22, NFR-04)
- 후속 과제: ① 어느 서비스인지 선정 (비용 단가가 나와야 O5 계산 가능)
  ② 빌드·프리뷰 산출물 엔티티를 ERD 에 추가 (`docs/traceability.md` 공백 참조)
