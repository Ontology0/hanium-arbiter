# HITL 정책 비교 실험

사람을 대리하는 개인 에이전트 사이의 **미확인 인계·결정 담당자 부재·협업 교착**을 중심으로, 내장 시나리오를 고정 턴 상한·주기적 HITL·온톨로지 기반 적응형 HITL에 각각 적용합니다. 작업 성공 여부·대화 이벤트 수·개입 요청 수를 비교하며, 사실·요구사항 충돌도 별도 사례로 포함합니다. API 키나 모델 서버 없이 실행할 수 있습니다.

이 실험은 **통제 시뮬레이션**입니다. 실제 백엔드 정책과 검증기를 실행하지만, 에이전트 발언은 스크립트이고 사용자 응답은 자동화되어 있습니다. 성공은 산출물 JSON이 로컬 체크리스트를 충족했다는 뜻이며 외부 메시지 전달이나 실제 구현 코드의 기능 성공을 검증한 결과가 아닙니다. 실제 LLM의 품질, 사람의 업무 부담, 토큰 절감 효과를 입증하는 실험으로 사용하지 않습니다.

## 실행

`hanium-arbiter/` 루트에서 실행합니다.

```bash
PYTHONPATH=backend python experiments/run_comparison.py --output experiments/results/latest
```

기본 설정은 누적 18턴, 주기적 개입 4턴 간격, 적응형 정체 창 3턴입니다. 조건을 변경하면 결과를 별도 폴더에 보관하세요.

```bash
PYTHONPATH=backend python experiments/run_comparison.py \
  --output experiments/results/cap12 \
  --max-turns 12 --periodic-every 4 --stall-window 3
```

세 정책은 같은 턴 상한과 같은 시나리오 생성기를 사용합니다. 모든 정책의 자동 사용자 응답은 카드에 시나리오의 `oracle_choice`가 있으면 그 선택을, 없으면 `continue`를 고릅니다. 둘 다 없는 카드는 임의로 답하지 않고 실행 오류로 남깁니다. 에이전트의 후속 이벤트는 같은 생성기에서 실제 결정 내용에 따라 분기합니다.

## 결과 읽기

| 파일 | 내용 |
|---|---|
| [results/latest/report.md](results/latest/report.md) | 생성된 한국어 결과 보고서, 비교표와 해석 한계 |
| [results/latest/summary.json](results/latest/summary.json) | 정책별 집계, 조건, UTC 실행 시각, Git revision·브랜치·변경 상태, 실제 소스 SHA-256 |
| [results/latest/runs.csv](results/latest/runs.csv) | 모든 시나리오·정책 조합의 종료 상태와 지표 |
| `results/latest/sessions/*.json` | 주입 이벤트, 자동 사용자 답변, 최종 상태와 체크리스트 검증 결과 |

동일 출력 경로로 다시 실행하면 같은 이름의 산출물을 갱신합니다. 집계에 사용한 세션의 목록은 `summary.json`의 `runs`로 확인합니다. 삭제된 시나리오의 예전 파일이 남아 있더라도 집계에는 포함하지 않습니다. 같은 소스와 설정에서 지표는 재현되지만 실행 시각과 세션 식별자는 실행마다 달라집니다.

각 시나리오·정책 조합은 한 번씩 실행하고, 실패·미판정·상한 초과를 전체 실행 분모에서 제외하지 않습니다. 성공 여부가 확인되지 않으면 `success: null`로 보존하며 실패(`false`)와 별도로 집계합니다. 확인 성공률은 전체 배정 실행 중 성공이 확인된 비율입니다. 실행 예외도 행과 세션으로 저장한 뒤 나머지 조합을 진행하며, 예외가 하나라도 있으면 명령은 종료 코드 1을 반환합니다. 작업 실패나 상한 소진 자체는 실험 실행 오류가 아닙니다.

토큰은 **미측정**입니다. JSON의 `null`과 CSV의 빈 토큰 칸은 0토큰을 의미하지 않습니다. 개입 요청 수도 실제 사람의 노동 시간과 같지 않으며, 요청 생성이 외부 사용자나 Slack에 실제 전달되었다는 뜻도 아닙니다. 성공한 실행만의 평균 턴은 정책마다 성공한 사례 집합이 다를 수 있으므로 전체 평균·성공률과 함께 읽어야 합니다.

## 재현과 검증 범위

시나리오마다 의도된 사용자 결정을 알고 있는 자동 응답기를 사용하므로 이 결과는 개입 처리 경로를 검증합니다. 일부 시나리오는 특정 결정 이후에만 후속 산출물을 내도록 설계되어 있습니다. 작은 개발용 사례에서 보인 성공률 차이를 실제 에이전트 환경의 성능 차이로 일반화하지 않습니다. 실제 대화의 한 차례 교환만으로 무한 대화라고 단정할 수도 없습니다. 결정적 실행의 반복을 독립 표본으로 세거나 통계적 유의성을 주장하지 않습니다.

평가 하네스 테스트는 전체 조합과 실패 실행의 보존, 동일 응답 정책, 토큰 미측정 표시, 결과 파일 대응을 확인합니다.

```bash
PYTHONPATH=backend python -m pytest tests/test_experiments.py
```

실제 모델과 사용자에 대한 결론을 내려면 별도로 수집·분리한 협업 사례, 개입 필요성에 대한 독립 라벨, 실제 사용자 응답, 전체 모델 호출의 사용량과 소요 시간이 필요합니다.
