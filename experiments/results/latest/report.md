## 실험 범위와 질문

사람을 대리하는 개인 에이전트 사이에서 인계 확인이 끝나지 않거나 결정 담당자가 없어 협업이 멈추는 상황을 중심으로, 개입 시점을 달리하면 정해진 작업 조건을 충족하는지와 대화 이벤트·개입 요청 수가 어떻게 달라지는지 확인한다. 사실·요구사항 충돌도 별도 사례로 포함한다. 실제 실행한 백엔드 정책과 로컬 체크리스트 검증기의 결과를 집계했다.

**본 결과는 스크립트 에이전트와 자동 사용자 응답을 사용한 통제 시뮬레이션이다. 실제 LLM 실험이나 사람 대상 사용자 연구가 아니다.** 실제 API 호출·토큰 비용·응답 지연·사용자 판단 시간은 측정하지 않았다.
성공은 각 사례의 산출물 JSON이 로컬 체크리스트를 충족했다는 뜻이다. 외부 메시지 전달이나 실제 구현 코드의 동작을 검증한 결과가 아니다.

고정 턴 상한 정책은 질문 없이 상한까지 진행한다. 주기적 정책은 정해진 간격으로 질문한다. 적응형 정책은 온톨로지의 위임·대기 관계·주장·근거·충돌·진행 상태와 정체 규칙에 따라 개입 요청을 만든다. 정책별로 다른 입력 문장을 따로 꾸미지 않고 동일한 시나리오 생성기를 사용하며, 결정 후 대화 분기는 선택된 결정에 따른다.

이 실행에서 적응형 정책의 전체 대화 턴 수는 주기적 정책과 같았다.
개입 요청 수가 달랐던 사례는 정상적인 긴 작업(주기적 1건, 적응형 0건)이다.

확인 성공률은 전체 배정 실행 중 성공이 확인된 비율이다. 미판정은 분모에 남기되 실패 판정과 별도로 센다. 평균 턴(전체)은 실패·미판정 실행도 포함한다. 성공만의 평균은 정책별로 성공한 시나리오 집합이 달라질 수 있으므로 직접적인 효율 우열로 해석하지 않는다. 개입 요청 수는 사람이 실제로 수행한 노동량이 아니라 시스템이 생성한 요청 수이다.

## 해석 범위와 한계

- 내장 시나리오는 개발자가 작성한 소규모 기능 검증용 사례이다. 외부 벤치마크나 무작위로 수집한 실제 협업 대화를 대표하지 않는다.
- 일부 스크립트는 특정 사용자 결정 이후 후속 산출물을 내도록 설계되어 있다. 성공률 차이는 이 조건에서의 제어 흐름을 보여주며 실제 에이전트 협업에서의 성능 우월성을 입증하지 않는다.
- 사용자 응답기는 시나리오의 의도된 선택을 아는 oracle이다. 잘못된 선택, 응답 지연, 무응답과 사람의 부담은 이번 비교에 포함하지 않았다.
- 에이전트 이벤트에 구조화된 주장·근거가 제공된다. 자연어에서 온톨로지 항목을 정확하게 추출하는 능력은 별도 평가가 필요하다.
- 실제 대화의 단일 교환만으로 무한 대화를 확정할 수 없다. 미확인 인계와 확인된 실패를 구분해야 하며, 이번 실험은 의도적으로 작성한 교착 사례를 사용한다.
- 개입 요청 생성은 로컬 상태 변경이다. 개인 에이전트나 Slack의 실제 사용자에게 메시지를 전달했다고 해석하지 않는다.
- 각 결정적 사례는 한 번씩 실행했다. 반복 실행을 독립 표본으로 세지 않으며 유의확률·신뢰구간을 제시하지 않는다.
- 토큰 사용량은 미측정(null)이다. 대화 이벤트 감소를 토큰 비용 절감률로 바꾸어 주장하지 않는다.
- 개입의 적절성에 대한 독립 사람 라벨이 없어 불필요한 개입률·감지 정밀도·재현율은 산출하지 않았다.
