# 권한 브리핑 실제 모델 연결 점검

합성 대화 한 사례를 실제 Codex CLI에 보낸 두 번의 점검 기록이다. 동일 프롬프트의 반복 실험이 아니며 탐지 정확도나 일반 성능 지표로 사용하지 않는다.

| 기록 | 입력·변경 | 관찰된 권한 분기 | 실측 입력/출력 토큰 |
|---|---|---|---|
| [시도 1](attempt-1.json) | 다른 소유자의 배포 승인권이 겹치는 합성 대화 | `authority_gap`: 모델이 실제 업무인 `approve` 대신 `choose-approval-precedence`를 추출해 기대한 충돌 분기와 불일치 | 14,969 / 362 |
| [시도 2](attempt-2.json) | 업무 행동과 권한 조정 행동을 구분하도록 추출 지침 보완 | `cross_owner_conflict`: 동일 범위의 `approve` 권한 보유자와 두 소유자를 반환 | 15,048 / 370 |

두 기록 모두 모델 호출과 토큰은 실제 측정값이다. 대화와 위임 정보는 시험용이며 실제 Slack 사용자·소유자의 승인 기록이 아니다. 원문 인용의 메시지 ID와 정확한 문자열 일치는 코드에서 확인했지만, 인용을 해석한 의미의 타당성 전체가 자동 검증된 것은 아니다.

두 번째 결과의 결정 항목을 고정한 채 로컬 API에서 관련 두 소유자의 승인을 기록한 우선순위를 넣으면 `authorized`와 `검토봇B`가 반환되며 사람 질문 후보가 0개가 되는 것도 확인했다. 이 재판정은 모델을 다시 호출하지 않는다. 로컬 운영자의 입력을 원격 소유자의 실제 신원·동의 인증과 동일시하지 않는다.

관찰된 한계: 언어 모델의 결정 대상·행동 정규화 오류는 후속 권한 규칙의 결과를 바꿀 수 있다. 업무 범위별 독립 라벨 데이터와 사람 검토를 통한 탐지 평가가 추가로 필요하다.
